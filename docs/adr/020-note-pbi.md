# 020: 付箋に関係する PBI を付ける

2026-11-25。オーナー方針「付箋まわりを最優先。付箋を追加できることの拡充」からの仕事（#29）。付箋は一言だけで、どの PBI に関係する仕事かを残せず、Issue にするとき（ADR 019）に親 PBI を毎回探し直していた。

## 判断

- **付箋が持つのは PBI の Issue 番号だけ**（`pbi?: number`）。題は持たず、画面がボードの読み取り（GitHub が正本）から引く。ボードに無い番号は `#番号` だけを出す。
  - 題を写して持たない理由: GitHub で題が変わると付箋の題が古くなる。また、付箋の書き込みは誰でも任意の文字列を送れるので、「GitHub の題のように見える自由な文」を DO に置かない。
  - 付箋 DO は GitHub を読まない（ADR 016 の境界）。番号が本当に open な PBI かはここでは確かめない。確かめる必要がある場面（Issue 化の親）は、作成時に `createFromNote` が親を読み直して `parent_not_pbi`・`parent_closed` で止める（ADR 019 のまま）。
- **貼るとき**: 棚の一言入力の下に「関係する PBI」の選択（`#team-note-pbi`）。既定は「なし」で、選ばなければ今までと同じ付箋。選択肢はボードに表示中の open な PBI を先に、その他の open な PBI を後に（Issue 化の親 PBI と同じ並び）。`create` に任意の `pbi` を足し、複数行の一括でも同じ PBI を全部に付ける。貼ったら選択は「なし」に戻す（続けて別の仕事を貼るときに、意図しない PBI が付かないように）。
- **付け替え・外し**: 人だけの op `pbi`（`{ id, rev, pbi: number | null }`）。`rev` で競合を検出し、上げる。AI（`/mcp`）の op ではない（送ると 403 `human_only`）。画面では付箋の上で `P`、または本文の下の `#番号 題` か hover の「PBI」ボタン。一覧（listbox）で選び、**Enter かクリックで保存、Escape で取り消し**。矢印で動かすたびには保存しない（閉じた select の `change` は矢印ごとに起きるため、一覧形式にして決定を明示する）。
- **Issue 化の初期値**: 「Issue に」を開いたとき、付箋の PBI を親 PBI の初期値にする。下書きがあれば下書きが優先（ADR 019 のまま）。open でない PBI は候補に無いので「なし」になる。
- **ボードの PBI 行からの入口**: 左セルの担当者の行の右端に「＋付箋」。押すと詳細は開かず、棚の一言入力へ移り、その PBI を選んだ状態にする（棚がたたまれていれば開く）。左セルの最小構成（DESIGN.md）を崩さないよう、hover・focus のときだけ見せる。付箋が無効（棚が出ていない）・全画面・Close 済みの PBI では出さない。
- **1 回だけ送る**: 一覧の Enter の連打・押しっぱなし・ダブルクリックでも送るのは 1 回。比べる値と rev は、選んでいる間に再取得された最新の付箋から取る（2 回目を古い rev で送ると、自分の操作なのに「他の人が変更した」と出るため）。
- **操作ボタンは本文の幅を取らない**: 付箋の操作（PBI・Issue に・×）は右上に重ね、hover・focus のときだけ見せる。見えない間も grid の列を取ると、約 240px の棚で一言が数文字ずつ折り返す（ボタンが 3 つになって目立った）。PBI 行の「＋付箋」も同じ理由で担当者の行の右端に重ね、担当者名の幅を削らない。
- **ボードの読み取りは軽く**: 棚は PBI の番号・題・状態だけを `Whiteboard.pbiLanes()` で読む。ボードを描くたびに状態全体を複製しない。
- **AI は読むだけ**: `notes_list` は付いている付箋にだけ `pbi`（番号）を返す。題は返さない（手元の AI は GitHub で読める）。

## 採らなかった案

- **題も付箋に写す**: 上記のとおり、古くなるのと、自由な文を正本らしく見せるため。
- **付箋 DO が PBI かどうかを GitHub に確かめる**: 付箋 DO に GitHub の読み取りを持ち込み、GitHub の障害で付箋が貼れなくなる。ラベルの誤りは人が画面で付け替えられ、Issue 化の時点では必ず確かめる。
- **AI にも付け替えさせる**: AI は案を付けるだけ（ADR 016 M1）。分類の付け替えは人の判断。
- **閉じた select で矢印ごとに保存**: 矢印で通り過ぎた PBI ごとに書き込みが走り、競合と rev の上昇を招く。

## 検証

- 別 context の独立検証（2026-11-25）: 1 往復目は要修正 1 件（一覧の二重送信で偽の競合）と軽微 8 件。直したもの: 二重送信、軽い読み取り、「＋付箋」が幅を取る、送信中に選び直した PBI を消さない、付箋が読み込み中・エラーのときは「＋付箋」を出さない、ショートカットの確認を実際の N/P で行う、一覧のクリックの試験。あわせて、Issue 化ダイアログの `close`（後から届く）が、閉じた直後に開いた PBI の一覧からフォーカスを奪って閉じる競合を直した。残したもの: 下書きがあると PBI の初期値より下書きが優先（ADR 019 の規則どおり）。

- `tests/team-notes.test.ts`: 貼るときの任意の `pbi`（一括の全部に付く）、付け替えと外し、古い rev は 409 で最新を返す、不正な番号（0・負・小数・文字列・真偽・安全でない整数・欠落）は何も保存しない、AI は付け替えられない。
- `tests/mcp.test.ts`: `notes_list` は付いた付箋にだけ `pbi` を返す。
- `tests/browser/note-pbi.spec.ts`（1920×1080・2560×1440）: キーボードだけで選んで貼る（選択の上の 1 文字でボードのショートカットが起きない）、題がボードから出て付箋の幅に収まる、貼った後は「なし」に戻る、Issue 化の親の初期値、`P` で外す（矢印では保存しない）・Escape で取り消す、PBI 行の「＋付箋」がクリックでもキーボードでも詳細を開かずに入口になる、付箋が無効なら出さない、付け替えの競合で最新を表示、結果不明は再送しない。
